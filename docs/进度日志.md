## 当前系统概览

一套**完全本地、离线**的语音对话 + 真人形象数字人：

```
你对麦克风说话 → VAD(Silero) → STT(Whisper large-v3-turbo)

 → Ditto 数字人生成说话视频(抠像+合成到背景) → 浏览器播放(带待命微动循环)
```

### 一、启动脚本整理

### 二、【重要坑】系统代理污染本机健康检查
- WSL 里有系统代理 `http_proxy=172.30.16.1:10808`(Windows 上的 clash/VPN，网关同主机)。
- `curl` 健康检查走代理 → 代理连不上本机 8902 却回 **503** → curl 退出码 0 → 脚本**误判"服务已在运行"跳过启动** → 端口无人 → 浏览器 `ERR_CONNECTION_REFUSED`。
- 修:三个脚本都加 `export no_proxy="127.0.0.1,localhost,::1,${LLM_HOST}"`。这也保证管线里 Python 的 urllib POST 音频、requests 调 LLM 不被代理劫持。

### 三、降延迟优化(两项，已验证)
- **人脸注册缓存**(`_CachedRegistrar`):同一照片只做一次人脸检测/特征提取，之后每句直接返回缓存(重建顶层 dict+list 容器避免污染)。省 ~1s/句。
- **抠图开关**(`--skip-mask`/`AVATAR_MATTE=0`):关掉则跳过 RVM 抠像+背景合成，用照片原背景，视频流 copy 只合音频(`_mux_audio`)。待命循环同步跟随开关(背景一致)。
- **实测**(1.5s 测试音频):抠图开 ~5.5s → 抠图关 **~3.2s**(省约 40%)。抠图模式在**服务启动时定死**，已在跑要改需先 `stop.sh`。

### 四、又踩一次 pkill 自杀
- 重启服务时把 `pkill -9 -f 'avatar_service[.]py'` 和 `nohup ... avatar_service.py` 写同一条 bash → pkill 正则匹配到本 shell 命令行里的 `avatar_service.py`，SIGKILL 掉自身。**教训:杀与启必须分成两条命令**。

### 三、真人数字人选型调研
- 全身高保真扩散（**SoulX-LiveAct** 6fps/单卡、**LiveAvatar** 需48G+/多卡）→ 单卡 5090 不现实；FP4 是计算精度非权重量化，救不了显存。
- 结论：单卡实时真人档 = **Ditto**（蚂蚁, 8GB, 4090上音频驱动42fps, Apache2.0）为最优；EchoMimicV3 备选。

### 四、Ditto 真人形象（本日主线，已跑通）
- 独立 py3.10 venv；**PyTorch 后端**（`ditto_pytorch` + `v0.4_hubert_cfg_pytorch.pkl`）避开 TensorRT8.6 的 Blackwell 不兼容；辅助模型走 onnxruntime CUDA。依赖：torch cu128 + onnxruntime-gpu 1.23 + mediapipe + cython 等。
- 实测：**~19-22fps**（PyTorch 后端，步数/分辨率都拉不动，卡在逐帧 eager 开销），**峰值显存仅 1.6G**（和语音管线共存无压力）。
- 口型档：`sampling_timesteps=50, smo_k_d=5, max_size=768`（用户选定）。
- **形象服务** `avatar_service.py`(8902)：POST 音频→Ditto生成→**RVM抠像**→合成到背景→mp4→SSE推播放页。
- **管线接入**：TTS handler 加 `avatar_mode`（环境变量 `DITTO_AVATAR_URL`），音频 POST 给 Ditto 不本地播放。
- **播放页** `player.html`：待命=**乒乓无缝循环**(静音生成的自然微动，正放+倒放)，回复=播视频，播完回待命。换照片重启服务会自动重建待命循环。
- **背景**：环境 ffmpeg libvpx 编不出 alpha webm → 改为**服务端抠像合成到背景**(默认暗色柔光渐变，可放 `avatar/background.png` 换场景图)，输出普通 mp4。**RVM 抠像 ~28fps、+0.1G 显存**。
- **延迟**：抠像+合成多加约 1×音频时长；回复长度是延迟主导项，已从 80 字调到**约 50 字**中间档。
