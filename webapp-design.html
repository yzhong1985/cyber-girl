04

技术选型

Choice · Rationale
模块方案为什么
音频上行v1 WebSocket 传 PCM16
v2 WebRTC		WS 简单，直接复用 speech-to-speech 现成的 socket/websocket 模式；WebRTC 后期升级，自带回声消除、抖动缓冲、低延迟
回声消除浏览器 getUserMedia{echoCancellation}比现在服务端"播放时不采集"的土办法好得多——能边说边听、真打断
VAD / 打断v1 服务端 Silero
v2 浏览器端 vad-web		先复用现成 Silero；客户端 VAD 更省带宽、打断更快
口型同步浏览器对正在播放的音频取音量 → 驱动 ParamMouthOpenY在客户端算，比现在服务端 SSE 推送更准、更跟手
STT / LLM / TTS原封不动，全在 5090 上重模型不动，只换前后的音频通道
前端单页 App · pixi-live2d-display · WebAudioLive2D 资源直接复用现有的
后端网关FastAPI + WebSocket把浏览器音频桥接到管线的收/发队列，替换 LocalAudioStreamer

07

三块硬骨头

务必先知道
阻塞级手机 / 局域网访问必须 HTTPS

浏览器麦克风权限 getUserMedia 只在 localhost 或 https 下可用。非本机访问要么自签证书（有警告），要么用 Tailscale / Cloudflare Tunnel 上真 TLS（顺带解决远程）。

需处理WSL2 网络暴露

服务在 WSL 里，局域网设备访问需在 Windows 上做 netsh portproxy 端口转发，或把 WS 网关直接跑在 Windows 侧。

需处理并发受限于单卡

一张 5090，LLM/TTS 一次只能顺序处理一路。自己单人用没问题；多人同时用要加请求队列 + 每会话上下文，且会排队。
